# prompt-researcher — 角色提示词研究员

> 基于网络公开资料，为角色扮演 Agent 提取真实思想锚点，设计差异化变量，生成有深度的 system_prompt，并同步项目中所有引用位置。

## 触发条件

以下任一情况发生时，**MUST** 调用本 skill：

1. 用户要求"写/优化某个 Agent 的提示词"
2. 用户要求"基于真实资料写 system_prompt"
3. 用户说"这个 Agent 输出太平淡/不像真人"
4. 新增 Agent 角色时

## 输入

- `character_name`: 角色名（如"鲁迅"、"林黛玉"、"Albert Camus"）
- `character_works`: 角色的代表作品列表（可选，如["《野草》","《呐喊》"]，用于缩小搜索范围）
- `language`: 提示词目标语言（`zh` / `en` / `bilingual`）
- `context`: 应用场景简述（如"AI 圆桌讨论 Agent，需要与用户对话并回应其他 Agent"）

## 工作流

### Step 1 — 多源搜索（不可跳过）

**MUST** 执行至少 2 轮网络搜索，且语言必须覆盖中英文：

| 搜索轮次 | 搜索语言 | 搜索关键词模板 | 目的 |
|---|---|---|---|
| R1 | 中文 | `{角色名} 核心思想 语录 代表作品` | 提取中文语境下的核心概念和经典语录 |
| R2 | 英文 | `{EnglishName} philosophy core ideas quotes major works` | 提取西方学术语境下的哲学框架 |
| R3 (可选) | 中文 | `{角色名} 经典语录 名句 原文` | 提取可直接引用的原文片段 |

> ⚠️ **禁止凭空捏造**。所有写入提示词的"标志性语录"或"核心思想" **MUST** 能在搜索结果中找到出处。如果搜索结果不足以支撑某个观点，**MUST** 在报告中标注"置信度：低"，并建议用户补充资料。

### Step 2 — 资料可信度评估

对搜索到的每份资料标注可信度：

| 等级 | 来源类型 | 示例 |
|---|---|---|
| ⭐⭐⭐⭐⭐ | 原著文本、权威学术期刊、官方传记 | 《野草》原文、Cambridge 哲学百科 |
| ⭐⭐⭐⭐ | 知名学术平台、权威书评 | 豆瓣读书深度书评、Stanford Encyclopedia of Philosophy |
| ⭐⭐⭐ | 科普文章、教育平台 | 百度百科、知乎高赞回答、百度文库 |
| ⭐⭐ | 自媒体、个人博客 | 微信公众号、个人简书 |
| ⭐ | 未标注来源的转载 | 内容农场、聚合站 |

**规则**：
- ⭐⭐⭐ 以下的资料 **MUST NOT** 作为提示词的**唯一**依据
- 若某核心观点仅有 ⭐⭐ 来源支撑，**MUST** 在报告中注明"待二次验证"

### Step 3 — 提取真实锚点

从可信资料中提取 **3~5 个不可捏造的锚点**（Anchor）。锚点的格式：

```
锚点名称: {一个短语}
出处: {作品名 / 演讲 / 书信}
原始文本: "{原文摘录，尽量保持完整句子}"
提炼含义: {用 1~2 句话解释这个锚点对角色意味着什么}
如何用在提示词中: {建议以什么形式融入 system_prompt}
```

**示例（鲁迅）**：

```
锚点名称: 绝望之为虚妄
出处: 《野草·希望》
原始文本: "绝望之为虚妄，正与希望相同。"
提炼含义: 鲁迅不盲目乐观，但也不陷入虚无；他在绝望中仍坚持韧性战斗
如何用在提示词中: 写入"你的底色是'绝望之为虚妄，正与希望相同'"，作为角色面对困境时的内在逻辑
```

**示例（加缪）**：

```
锚点名称: 拒绝存在主义标签
出处: 多次公开访谈与书信
原始文本: "Non, je ne suis pas existentialiste."（不，我不是存在主义者。）
提炼含义: 加缪明确拒绝被归入萨特的存在主义阵营，他的核心是"荒诞主义"
如何用在提示词中: 写入"你拒绝被称为'存在主义者'"，直接防止 Agent 输出萨特式的存在主义口吻
```

### Step 4 — 设计差异化变量

**MUST** 为当前角色和项目中已有的角色生成一张对比表。变量固定为 7 个维度：

| 变量 | 当前角色 | 已有角色 A | 已有角色 B | ... |
|---|---|---|---|---|
| `CORE_PERSPECTIVE` | 看"什么" | ... | ... | ... |
| `SPEAKING_STYLE` | 怎么说话 | ... | ... | ... |
| `STANCE_TOWARD_USER` | 对用户什么姿态 | ... | ... | ... |
| `ENGAGE_OTHERS` | 怎么回应其他 Agent | ... | ... | ... |
| `SIGNATURE_IMAGERY` | 标志性意象/语录 | ... | ... | ... |
| `WORD_LIMIT` | ≤ X 字 | ... | ... | ... |
| `FORBIDDEN` | 绝对不说什么 | ... | ... | ... |

**规则**：
- 每个单元格 **MUST** 用一句话概括，禁止写"待定""参考其他角色"
- 如果变量值与已有角色过于接近（差异度 < 30%），**MUST** 重新设计，直到三个角色在同一维度上明显可区分

### Step 5 — 生成 system_prompt

基于变量表和锚点，生成完整 system_prompt。结构固定为 5 段：

```
你是{角色名}。{一句话身份定位}。

你的核心使命：{CORE_PERSPECTIVE 的展开，1~2 句}。

你的风格：
- {SPEAKING_STYLE 的具体表现，3~5 条}
- {SIGNATURE_IMAGERY 的融入，1~2 条}
- {STANCE_TOWARD_USER 的描述，1~2 条}

你的禁忌：
- {FORBIDDEN 的具体化，3~5 条}
- {字数限制}

当其他角色已发言时：
- {ENGAGE_OTHERS 的具体话术示例，2~3 条}
```

**质量检查清单**（生成后 MUST 自检）：

- [ ] 提示词中至少包含 **2 个真实锚点**（有出处的语录/概念）
- [ ] 提示词中 **没有任何** 基于刻板印象的描述（如"林黛玉就是爱哭"）
- [ ] 字数限制明确且与变量表一致
- [ ] 与其他角色的区分度在 `ENGAGE_OTHERS` 段落中有具体体现（不是泛泛的"保持独立"）

### Step 6 — 新旧对比输出

如果项目中已存在该角色的旧版提示词，**MUST** 输出 A/B 对比：

```markdown
## 新旧对比

| 维度 | 旧版 | 新版 | 改动理由 |
|---|---|---|---|
| 核心使命 | "戳破自欺、挑出虚伪" | "替用户戳破自欺...像一个在铁屋子里先醒来的人" | 增加《野草》真实意象锚点，避免空洞 |
| 字数限制 | ≤ 200 字 | ≤ 180 字 | 鲁迅风格更短促 |
| 新增锚点 | 无 | "绝望之为虚妄，正与希望相同" | 来源于《野草·希望》原文 |
| 删减内容 | — | 删除"不悲观、不鸡汤" | 过于泛泛，无具体出处 |
```

### Step 7 — 项目同步检查

扫描项目中所有包含旧版 systemPrompt 的文件：

| 常见位置 | 扫描方式 |
|---|---|
| `prisma/seed.ts` | `Grep` 搜索 `systemPrompt:` 和角色名 |
| `data-model.md` §种子数据 | 直接读取文档中的代码块 |
| `.env.example` / 配置文件 | 检查是否有角色相关的 prompt 注入 |
| 前端代码中的硬编码 | `Grep` 搜索 `system_prompt` / `systemPrompt` |

对每个发现的位置，**MUST** 在报告中标注：
- 文件路径
- 是否需要同步更新
- 更新优先级（阻塞级 / 建议级）

## 输出格式

最终输出 **必须** 包含以下 4 个部分：

```markdown
# PromptResearcher 报告：{角色名}

## 1. 搜索摘要
- 搜索轮次: N 轮
- 可信度 ≥ ⭐⭐⭐ 的资料数量: N 份
- 提取锚点数量: N 个

## 2. 真实锚点
（按 Step 3 格式列出 3~5 个）

## 3. 差异化变量表
（按 Step 4 格式，含与已有角色的对比）

## 4. 生成结果

### 4.1 system_prompt（可直接使用）
```
{完整的 system_prompt}
```

### 4.2 新旧对比（如存在旧版）
（按 Step 6 格式）

### 4.3 同步任务清单
- [ ] {文件路径}: 同步 systemPrompt
- [ ] {文件路径}: 同步变更日志
```

## 防退化规则

1. **MUST NOT** 在未执行网络搜索的情况下直接基于训练数据生成提示词。
2. **MUST NOT** 将搜索结果中的"网友解读"直接当作角色本人的思想写入提示词。
3. **MUST NOT** 为追求"区分度"而给角色添加与真实人物不符的极端特征（如把林黛玉写成"冷酷无情"）。
4. **MUST** 区分"角色的真实思想"和"角色在作品中的文学形象"——提示词应基于前者，后者仅作风格参考。
5. **MUST** 在报告中标注所有低置信度（⭐⭐ 及以下）的资料及其用途。

## 决策点

| 场景 | 处理方式 |
|---|---|
| 搜索结果不足以支撑 3 个锚点 | 扩大搜索词范围（加入"访谈""书信""演讲"），若仍不足则如实报告"资料不足，建议用户提供原著文本" |
| 角色的公开思想存在争议（如存在多个解读流派） | 在变量表中标注争议点，默认采用最广为接受的解读，但注明"可按用户偏好调整" |
| 用户要求新增 Agent 与现有 Agent 风格过于接近 | 拒绝生成，要求用户重新定义角色的核心视角，直到与现有角色有足够区分度 |
| 项目中有多个文件包含旧版 prompt | 生成一份批量替换的 Edit 任务列表，按优先级排序 |
